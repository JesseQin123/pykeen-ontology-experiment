KGE validation · final report · 2026-10-17 · 17 experiments · PyKEEN 1.11

Do graph embeddings actually help on semantic ontology graphs?

The question: with PyKEEN-style graph embeddings, (1) can we discover real relationships the graph is missing, (2) do we get useful suggested connections, (3) does it help performance on large graphs, and (4) given two graphs that use different terms for the same entities, will the embeddings find the correspondences and suggest mappings? As the question itself put it, the plural of anecdote is not data. This report turns each claim into a measurable experiment, pairs every experiment with a non-embedding baseline, and converges on a method you can follow.

Findings and recommended practice

1. Discovering relationships the graph is missing

True, but much weaker than it looks

We trained on the 2020 Gene Ontology and scored predictions against the links curators actually added by 2026. On genuinely new relationships, fusing embeddings with label text reaches Hits@10 of 30–36% (37% on a 2018 → 2020 replication), against 2.5–17% for rule learners. Embeddings do find relationships that graph search cannot reach. But the same methods score MRR ≈ 0.5 on the usual random hold-out and only 0.10–0.19 prospectively, so the standard evaluation overstates real ability 3–5 times. Also, 58% of the links curators added were already implied by the old graph, and a simple reasoner puts 93% of those in its top 10.

Practice: run a reasoner first to collect the "free" half; generate candidates by fusing embeddings with text; then filter with an LLM and experts.

2. Useful suggested connections

Usable only with filtering

Changing only the random seed changes the top suggestion 41% of the time. For random concepts, about 0.3% of suggestions were adopted by curators within six years. Three frontier LLM judges rating blind (pairwise kappa 0.75–0.81) accept about 9% of top suggestions. A pipeline of embedding candidates plus an LLM majority vote does work: suggestions that pass the vote later came true 89 times as often as rejected ones, and the vote kept 87% of the suggestions that came true.

Practice: fuse several seeds and models to reduce noise; use an LLM vote as the first filter; send what remains to an expert review queue and track the outcomes to measure real precision.

3. Performance on large graphs

Faster queries, not better accuracy

On a 3-million-node graph, 3-hop traversal has a p99 of 1.5 s, while an HNSW index over embeddings answers in 0.01 ms with 99.9% recall on real embeddings. Accuracy, however, falls with size. On the same test questions, as YAGO grows from 5k to 123k entities, RotatE MRR under a fixed configuration falls from 0.62 to 0.15. Training to 150 epochs reaches only 0.16, and a lower learning rate only 0.21. Rules degrade from 0.64 to 0.48.

Practice: use embeddings plus ANN for approximate "related concept" queries and keep exact structural queries in the graph database; retune at every change of scale; place new concepts through a text-to-embedding mapping instead of retraining each time.

4. Naturally crossing semantic taxonomies

Does not happen on its own

On two independently built real anatomy ontologies (OAEI, mouse vs. human), every structure-only method without anchors is at chance level, including the strongest one we tried, Gromov-Wasserstein optimal transport (Hits@1 0.07%). Inside a combined pipeline, though, embeddings contribute: with concepts whose labels match exactly used as automatic anchors, text plus graph embeddings raises Hits@1 on the hard pairs from 83.4% to 88.6%. The full pipeline (text + graph embeddings + Claude verification) reaches F1 0.939; AML, the track winner, has 0.941.

Practice: exact label matches as anchors → text embeddings with synonyms to generate candidates → graph embeddings trained jointly over the anchors as a structural correction → LLM verification of each pair.

How the experiments were designed

Testing directly on the original ontology was not possible for two reasons. We did not have it, and judging whether a suggested link is correct requires knowing the answer in advance, which a working ontology does not provide. That is why the original observations could only be anecdotal. We used five public datasets with ground truth instead, each assigned to one question.

DatasetWhat it isWhy we chose itTests

Baselines: popularity (always recommend the most frequent answer); the published AnyBURL rule learner, one of the strongest explainable methods in the literature; a logical reasoner using is_a transitivity only; text embeddings of concept names and definitions (bge-large); and an alignment method that uses no embeddings, only which anchors appear in each concept's neighbourhood.

LLMs: a local qwen3.5-27B, and Claude Opus 5.5, GPT-6.1 and Gemini 4 through a relay. LLMs were used in three roles: re-ranking candidates, generating answers with no candidates, and acting as blind judges.

Protocol: every method uses the same filtered ranking, predicts both head and tail, and takes the expected rank on ties. Key comparisons carry paired-bootstrap 95% confidence intervals.

A configuration that works well at 5k nodes stops working at 123k. Training longer does not recover it; lowering the learning rate to 2e-3 helps somewhat (0.15 → 0.21) but stays far below the 0.62 seen on the small graph. Published RotatE results on YAGO3-10 reach about 0.49 with a dedicated configuration and much longer training. Accuracy on large graphs is not free: every step up in scale needs retuning and more compute. Rules pay a different cost: the rule index on full YAGO holds 479 million non-zeros.

Training cost is roughly linear, about 48 s per million triples per epoch on an M5 Pro. A 256-dimensional complex embedding of 100 million entities needs about 205 GB of parameters, which calls for a sharded training system such as PyTorch-BigGraph.

With the same LLM verifier, adding graph embeddings consistently helps: F1 rises from 0.932 to 0.939 with Claude, with hard-pair recall up 3.7 points, and from 0.929 to 0.937 with GPT. Here the graph embedding works as a structural correction. It knows whether two concepts' parents and parts line up, which fixes some mistakes that labels alone make. It does not work without the text and the anchors.

On the renamed WordNet views, joint training over 30% anchors also matched all 11 renamed relation types to their counterparts in the other view. That matters when two ontologies name their properties differently: entity anchors can recover the relation mapping as well.

The failures show that one configuration does not suit every model; they are not the models' ceilings. They also mean a good result seen under one setup may not reproduce with another model or configuration. TransE cannot represent symmetric relations and reaches only 1.8% Hits@1 on WordNet.

The converged method

  1. Completing an ontology: (1) run a logical reasoner to collect the implied half; (2) fuse RotatE, TransE and text embeddings to generate candidates; (3) use AnyBURL rules to give explainable paths where they exist; (4) filter with an LLM vote; (5) have experts review. On GO, fusion raises the top-10 hit rate on genuinely new relationships from 17–27% for single methods to 36%.
  2. Suggested connections: do not trust a single suggestion from a single run. Fuse several seeds and models; use an LLM vote as the first filter, which cuts review volume to about 7%; record expert decisions to measure real precision and tune thresholds.
  3. Large graphs: use embeddings plus HNSW for approximate "semantically related" queries and the graph database for exact paths and constraints. Retune whenever the graph grows. Place new concepts with a linear text-to-embedding mapping and retrain on a schedule.
  4. Cross-ontology mapping: exact label matches as anchors → text embeddings with synonyms for candidates → joint graph embedding over the anchors as a structural correction → LLM verification of each pair → a final consistency check (for example LogMap's logical repair, which we did not run). On OAEI Anatomy this reaches F1 0.939.
  5. Evaluation: do not rely on random hold-out. With version history, test prospectively (train on an old release, score on a newer one). Report entailed and genuinely new links separately. Always compare against a strong rule baseline, a reasoner and a text baseline. Evaluate suggestions by blind rating with positive and negative controls mixed in.

What it takes to confirm this on the original ontology

These findings come from public data. A private ontology differs in two ways: no LLM has seen it, and its terms and structure may be less regular than GO's. The last step has to happen on that data.

  1. Three inputs: the ontology itself (or an anonymized sample), the PyKEEN configuration that was used, and the specific examples that looked genuinely useful.
  2. Reproduce the anecdotes: check whether the rule baseline, the reasoner and the text baseline find the same examples. If they do, those discoveries did not need embeddings.
  3. If the ontology has version history: apply the GO prospective protocol as is; the code is ready.
  4. Blind review: sample 50 suggestions each from embeddings, rules and random candidates, shuffle them, and have domain experts and the three LLM judges rate them. Expert ratings are the ground truth; the LLM ratings show how much expert work an LLM could take on.
  5. If there is a second vocabulary to map: apply the four-step OAEI pipeline as is and have experts review 100–200 of the resulting pairs.

Limitations

  • Hyperparameter search was limited. RotatE reached published performance on WordNet but not on full YAGO, and many PyKEEN models failed under the shared configuration.
  • "Came true in GO within six years" is a strict lower bound, because curators do not fill every gap. Blind rating offsets this, but the LLM judges are conservative too and accept only 68% of links curators added.
  • LLMs have memorized much of the public ontologies, so their scores on GO and OAEI may be inflated.
  • Only the OAEI Anatomy track was used; larger tracks such as Bio-ML were not run, and the pipeline does no logical repair.
  • Traversal latency used single-threaded scipy rather than a dedicated graph database. Gemini's relay quota ran out during the last experiment, so the full WordNet re-ranking uses only GPT and Claude.

Reproducing

The code is in the private repository JesseQin123/pykeen-ontology-experiment. Training ran locally on an M5 Pro. LLM and embedding inference ran on hosted endpoints: a relay for the LLMs, and bge-large on OpenRouter, whose vectors match the local bge-large checkpoint with cosine 1.00000. Every number traces to results/SUMMARY.json, results/STATS.json and each experiment's own JSON file.
