图嵌入在语义本体图上到底有没有用

同事的问题：用 PyKEEN 做图嵌入，(1) 能不能发现图里漏掉的真实关系，(2) 能不能给出有用的连接建议，(3) 能不能提升大图上的性能，(4) 两张用不同术语描述同一批实体的图，嵌入能不能自动找出对应关系。他自己也说"复数的轶事不等于数据"。这份报告把每个说法变成可测量的实验，每个实验都配了不用嵌入的对照组，最后收敛成一套可以直接照做的方法。

结论与推荐做法

1. 发现图里漏掉的真实关系

成立，但比看起来弱得多

用 2020 年版的 Gene Ontology 训练，预测 2026 年专家真正新加的边。对真正新的关系，嵌入 + 文本融合的 Hits@10 为 30% 到 36%（2018→2020 的复现为 37%），规则学习器只有 2.5% 到 17%。嵌入确实能找到图搜索够不到的关系。但同样的方法在"随机藏边"测试里 MRR 约 0.5，在这里只有 0.1 到 0.19，常见的评估方式把真实能力高估了 3 到 5 倍。另外，专家新加的边有 58% 是旧图里已经能推出来的，一个简单的推理器就能把其中 93% 排进前 10。

怎么做：先跑推理器，拿到"免费"的那一半；再用嵌入 + 文本融合生成候选；最后交给 LLM 和专家筛选。

2. 给出有用的连接建议

需要过滤才可用

只换随机种子，排名第一的建议有 41% 会变。对随机概念给出的建议，6 年内被专家采纳的只有约 0.3%。三个前沿 LLM 盲审（两两一致性 kappa 0.75 到 0.81）只认可约 9% 的第一名建议。但"嵌入候选 + LLM 投票过滤"这条流水线有效：通过过滤的建议，后来成真的比例是被拒建议的 89 倍，并且保留了 87% 后来成真的建议。

怎么做：多个种子、多个模型做融合，降低偶然性；用 LLM 投票做第一道过滤；剩下的进专家审核队列，按审核结果统计真实准确率。

3. 提升大图上的性能

查询速度成立，准确率不成立

300 万节点的图上，3 跳遍历的 p99 是 1.5 秒；嵌入加 HNSW 索引单次查询 0.01 ms，在真实嵌入上召回率 99.9%。但准确率随规模下降：同一组测试题，图从 5 千节点扩到 12 万节点，相同配置下 RotatE 的 MRR 从 0.62 跌到 0.15；训练到 150 个 epoch 也只有 0.16，把学习率降到 2e-3 后也只到 0.21；规则方法只从 0.64 降到 0.48。

怎么做："找相关概念"这类近似查询用嵌入 + ANN；精确的结构查询继续交给图数据库；每次扩大规模都要重新调参；新概念用"文本 → 嵌入"映射放置，不用每次都重训。

4. 自然地跨越不同术语体系

不会自然发生

在两套独立构建的真实解剖本体上（OAEI，小鼠 vs 人类），不给锚点时，所有纯结构方法都是随机水平，包括最强的 Gromov-Wasserstein 最优传输（Hits@1 0.07%）。但在组合流程里嵌入有真实贡献：以名称完全相同的概念作为自动锚点，"文本 + 图嵌入"对难例的 Hits@1 从 83.4% 提高到 88.6%。完整流程（文本 + 图嵌入 + Claude 核验）的 F1 是 0.939，OAEI 冠军 AML 是 0.941。

怎么做：名称完全匹配作为锚点 → 文本嵌入（含同义词）生成候选 → 用锚点联合训练图嵌入，作为结构修正 → LLM 逐对核验。

Summary in English (for the colleague)

  • Finding missing relations: real, but much weaker than benchmarks suggest. Trained on GO 2020 and scored on what curators added by 2026, embedding + text fusion reaches Hits@10 0.30–0.36 on genuinely new is_a links (0.37 on a 2018 → 2020 replication), versus 0.03–0.17 for rule learners. The same methods score MRR ≈ 0.5 on random hold-out but 0.10–0.19 prospectively. 58% of curator additions were already entailed, and a transitivity reasoner ranks 93% of those in its top 10. On random hold-out, a real AnyBURL beats RotatE (MRR 0.517 vs 0.487, 95% CI of the gap [+0.023, +0.035]).
  • Suggested links: unstable alone, useful with filtering. Top-1 suggestions change 41% of the time across seeds. Three frontier LLM judges (Claude Opus 5.5, GPT-6.1, Gemini 4; kappa 0.75–0.81) accept about 9% of top-1 GO suggestions. An embedding-candidates → LLM-majority-vote pipeline enriches suggestions that later came true 89-fold and keeps 87% of them.
  • Scale: faster approximate queries, not better accuracy. HNSW over embeddings answers in 0.01 ms (99.9% recall) where 3-hop traversal hits 1.5 s p99 at 3M nodes. With a fixed configuration, RotatE MRR falls from 0.62 to 0.15 as YAGO grows from 5k to 123k entities; 150 epochs don't fix it, and a lower learning rate only reaches 0.21. Rules degrade from 0.64 to 0.48.
  • Cross-taxonomy mapping does not emerge on its own. On OAEI Anatomy (independently built ontologies), every seed-free structural method is at chance, optimal transport included. With exact-label anchors, joint KGE lifts text-embedding matching on hard pairs from 0.834 to 0.886 Hits@1. The full pipeline (text + KGE + LLM verification) reaches F1 0.939; AML, the track winner, has 0.941.
  • LLMs: frontier LLMs re-ranking structural candidates double or triple Hits@1. On GO an LLM alone matches that, because it has memorized GO: Claude recalls 75% of old GO IDs. On OAEI, structural candidates beat LLM-only by 14 points. For a private ontology no LLM has seen, the structural signal should matter more.

实验是怎么设计的

直接在同事的图上测有两个问题：一是我们手上没有他的图；二是要判断"嵌入推荐的边对不对"，必须事先知道正确答案，而他的图里没有答案，所以他只能凭感觉。我们用五个有标准答案的公开数据集，每个负责检验一个问题。

数据集是什么为什么选它检验
WordNet（WN18RR）英语词汇的概念网，4 万个概念，11 种关系最接近"语义本体"的标准基准，方便和文献对比问题 1、2 热身
Gene Ontology生物学本体，约 4.5 万个概念，由专家持续维护，每月发布新版本有历史版本：用 2020 年版训练，用 2026 年专家真正新加的边检验。这是唯一能检验"真发现"的方式，文献里没找到用 GO 这样验证 PyKEEN 类嵌入的工作问题 1、2 关键检验
YAGO3-10从维基百科抽取的知识图谱，12 万实体、108 万条边足够大，可以测图变大之后的变化问题 3
OAEI 解剖本体小鼠解剖学（2,744 个概念）和人类解剖学（3,304 个概念），不同团队独立构建，有 1,516 对专家标注的对应关系就是"两张图、不同术语、同一批东西"的真实场景，可以和历年参赛系统直接比较问题 4
FB15k-237Freebase 的子集，比 WordNet 稠密得多对照图的稀疏程度对对齐的影响问题 4 辅助

对照组：流行度基线（总是推荐最常见的答案）；正式的 AnyBURL 规则学习器（文献中最强的可解释方法之一）；只用 is_a 传递性的逻辑推理器；只用概念名称和定义的文本嵌入（bge-large）；以及"不用嵌入、只看邻居里有哪些锚点"的对齐方法。

LLM：本地 qwen3.5-27B，以及通过中转站调用的 Claude Opus 5.5、GPT-6.1、Gemini 4。LLM 用在三处：对候选重新排序、不给候选直接生成答案、充当盲审评审。

评估协议：所有方法用同一套 filtered ranking，同时预测头和尾，分数并列时取期望排名。关键对比都做了配对 bootstrap，给出 95% 置信区间。

在同一个 LLM 核验者下，加入图嵌入稳定提高结果：Claude 核验时 F1 从 0.932 升到 0.939，难例召回提高 3.7 个点；GPT 核验时从 0.929 升到 0.937。图嵌入在这里的角色是"结构修正"：它知道两个概念的上下位和组成关系是否吻合，能纠正一部分只看名称造成的误判。但它离不开文本和锚点。

收敛版：针对同事的问题，可以怎么做

  1. 补全本体，找漏掉的关系：(1) 先跑逻辑推理器，拿到可推导的那一半；(2) 用 RotatE、TransE 和文本嵌入做融合，生成候选；(3) 可解释的部分用 AnyBURL 规则给出路径；(4) LLM 投票过滤；(5) 专家审核。在 GO 上，融合把真正新关系的前 10 名命中率，从单一方法的 17% 到 27% 提高到 36%。
  2. 连接建议：不要相信单次运行的单条建议。多个随机种子、多个模型取融合结果；LLM 投票做第一道过滤，把审核量降到约 7%；专家审核的结果持续记录下来，用来统计真实准确率、调整阈值。
  3. 大图性能：需要"语义相近"的近似查询时，用嵌入 + HNSW；需要精确路径和约束时，用图数据库。每次扩大图的规模都重新调参。新概念用"文本 → 嵌入"的线性映射直接放置，再定期整体重训。
  4. 跨本体映射：名称完全匹配作为锚点 → 文本嵌入（含同义词）生成候选 → 带锚点的联合图嵌入做结构修正 → LLM 逐对核验 → 最后做一致性检查（例如 LogMap 的逻辑修复，本实验没有做）。在 OAEI 解剖本体上，这套流程的 F1 达到 0.939。
  5. 评估方法：不要只用"随机藏边"。有版本历史就做前瞻性测试（旧版本训练、新版本检验）；把"可推导"的边和"真正新的"分开报告；每次都和一个强规则基线、一个推理器、一个文本基线对比；建议类的结果用盲审评估，并混入正反对照。

要在同事自己的数据上做实，还需要什么

这里的结论都来自公开数据。同事的私有本体有两点不同：LLM 没见过它；它的术语和结构未必像 GO 那样规整。所以最后一步必须在他的数据上做。

  1. 向他要三样东西：本体本身（或脱敏样本）、当时的 PyKEEN 配置、让他觉得"真的有用"的几个具体例子。
  2. 复现他的轶事：看那几个例子在规则基线、推理器和文本基线里能不能同样找到。如果能，说明那些发现并不需要嵌入。
  3. 如果本体有版本历史：直接套用 GO 的前瞻性测试流程，这套代码已经写好。
  4. 盲审：从嵌入、规则、随机三种来源各抽 50 条建议，打乱后请领域专家打分，同时让三个 LLM 评审也打分。专家结果作为最终标准，LLM 结果用来估计能否让 LLM 分担一部分专家的工作量。
  5. 如果有第二套术语体系要映射：直接套用 OAEI 的四步流程，再请专家审核 100 到 200 对结果。

局限

  • 超参数只做了小范围搜索。RotatE 在 WordNet 上达到了论文水平，在全量 YAGO 上没有；PyKEEN 里不少模型在统一配置下训练失败。
  • GO 的"6 年内成真"是偏严的标准，专家不会补全所有遗漏，所以建议的真实准确率会高于这里的下限。盲审用来弥补这一点，但 LLM 评审也偏保守，对专家新加的边只认可 68%。
  • LLM 记住了不少公开本体的内容，GO 和 OAEI 上 LLM 的成绩可能偏高。
  • OAEI 只用了解剖学这一对本体，Bio-ML 等更大的赛道没有跑；流程里没有做逻辑一致性修复。
  • 遍历延迟用的是单线程 scipy，没有和专门的图数据库比。Gemini 在中转站上的额度在最后一组实验中用完，WordNet 全量重排序只用了 GPT 和 Claude。
